## 1. 通用约定

### 1.1 统一响应信封

所有接口（含错误）都返回同一信封结构：

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "traceId": "f4fd5c76803a4dd6aac5be464787c78f",
  "timestamp": 1792402809646
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | 业务码，**0 表示成功**，非 0 见第 2 节错误码表 |
| `message` | string | 成功恒为 `ok`；失败为可读中文原因 |
| `data` | object / array / null | 业务负载，失败时可能附带 `errors`/`allowed` 等辅助信息 |
| `traceId` | string | 请求链路 ID（32 位 hex）；客户端可用 `X-Trace-Id` 请求头指定，服务端回显 |
| `timestamp` | int | 服务端生成信封的毫秒时间戳 |

### 1.2 响应头

| 响应头 | 说明 |
|---|---|
| `X-Response-Time` | 服务端处理耗时（毫秒，两位小数，如 `14.36`） |
| `X-Trace-Id` | 与信封 `traceId` 相同 |
| `Access-Control-Allow-Origin` | `*`（前端可 file:// 直连） |

### 1.3 数值与缺失约定

- 所有**比率**为 0–1 的小数，保留 6 位小数（如 `0.181688` 即 18.1688%），前端自行乘 100。
- **计数**为整数；**分母**（`validSamples`/`denominator`）是该指标非空样本数，7/9/77/99 等缺失码已在清洗阶段置 NULL。
- 分母为 0 或不可计算时返回 `null`，不返回 0，避免把"无数据"误读成"0 风险"。
- 接口本身不缓存到客户端，服务端有 30 秒内存聚合缓存（`API_CACHE_TTL` 可调）。

### 1.4 数据来源

全部数字来自 SQLite `db/chronic_risk.db` 的 `fact_brfss` 明细表实时聚合，
服务以**只读**方式（`mode=ro` + `PRAGMA query_only`）连接，代码中不含任何硬编码统计量。

## 附录 C：编码约定与危险因素暴露定义

### C.1 编码约定（建库阶段已统一，接口按此取值）

1. **二值字段一律 0/1，且 1 = 字段名所描述的状态成立**。
   - `heavy_drink`：1 = 酗酒（由 `_RFBING6` 的 `2=是` 归一化而来）
   - `phys_activity`：1 = 有休闲运动（由 `_TOTINDA` 的 `1=是` 归一化而来）→ **无运动暴露 = 0**
   - `has_*`（8 个慢病标志）、`obese`、`multimorbidity`：1 = 是/成立
   - `medcost`、`diffwalk`：1 = 是
2. **有序分类保持原码**，不做 0/1 归一化：
   - `smoker3`：1 每日 / 2 部分日 / 3 曾经 / 4 从不
   - `genhlth`：1 优 / 2 很好 / 3 好 / 4 一般 / 5 差（**数值越大越差**）
   - `checkup`：1 一年内 / 2 两年内 / 3 五年内 / 4 五年以上 / **8 从未做过常规体检**
   - `persdoc`：1 只有一位 / 2 多位 / 3 没有
   - `menthlth` / `physhlth`：近 30 天不良天数（0–30）
3. 缺失码 7/9/77/99 等在清洗阶段已置 NULL，分母一律用该列非空计数。

### C.2 九项危险因素暴露定义（key 与 `agg_risk_factor.risk_factor` 完全一致）

| key | 中文名 | 暴露定义 | 分母 |
|---|---|---|---|
| checkup_over_1y | 一年以上未做常规体检（含从未体检） | `checkup > 1` | COUNT(checkup) |
| cost_barrier | 因费用而未就医 | `medcost = 1` | COUNT(medcost) |
| current_smoker | 现在吸烟（每日/部分日） | `smoker3 IN (1,2)` | COUNT(smoker3) |
| diff_walk | 行走困难 | `diffwalk = 1` | COUNT(diffwalk) |
| fair_poor_health | 自评健康一般或差 | `genhlth >= 4`（1 优 … 5 差） | COUNT(genhlth) |
| heavy_drink | 重度饮酒 | `heavy_drink = 1`（酗酒） | COUNT(heavy_drink) |
| no_personal_doctor | 无固定就诊医生 | `persdoc = 3`（1 一位 / 2 多位 / 3 没有） | COUNT(persdoc) |
| no_phys_activity | 过去 30 天无体育锻炼 | `phys_activity = 0` | COUNT(phys_activity) |
| obese | 肥胖 | `bmi >= 30`（等价 `obese = 1`，直接用 bmi 以免依赖派生列） | COUNT(bmi) |

> 关于 `checkup`：`checkup = 1` 表示"过去 12 个月内做过体检"（占 81.4%），
> 因此**"就医行为风险"用 `checkup > 1`**（2023 年 18.59%），而不是 `checkup = 8`（从未体检，0.64%）。
> 后者仅在需要单独说明"从未体检"时使用，不并入本组暴露率。

### C.3 与物化表的一致性

`/api/v1/risk/factors` 默认直接使用物化表 `agg_risk_factor`（9 项，按 key 排序，值与建库脚本逐字节一致）；
表不存在或为空时回退到按 C.2 谓词从 `fact_brfss` 直算，两条路径已验证结果相同。
响应中的 `source` 字段标明本次实际走的是哪条路径。

## 附录 D：分层与预测阈值口径

- 风险分层（/risk/stratify）：低 = 慢病数 0–1；中 = 2–3；高 = ≥4。共病定义沿用规格：慢病数 ≥ 2。
- 在线预测（/predict）风险等级：概率 < 0.10 低风险；0.10–0.30 中风险；≥ 0.30 高风险；`prediction` 阈值 0.5。
- 以上阈值是**服务层决策规则**（随响应 `thresholds` 返回），不改变模型输出的概率值。
