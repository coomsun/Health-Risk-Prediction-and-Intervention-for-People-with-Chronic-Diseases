> 数据源：CDC **BRFSS（Behavioral Risk Factor Surveillance System）LLCP** 微观数据 2019–2023 五个年度
> 获取途径：HuggingFace 镜像 `LoneWolfgang/brfss-llcp`（原始发布方美国 CDC 站点本机被 403 拦截）
> 原始副本：`data/raw/LLCP{2019..2023}.parquet` + `data/raw/dictionary/{dictionary,variables}.csv`
> 生成过程：`pipeline/01_download.py` → `pipeline/02_clean_spark.py`（PySpark 4.2.0 local[4]）→ `pipeline/06_build_db.py`
> 本文档数字与 `artifacts/metrics/pipeline_log.json`、`db/chronic_risk.db` 完全同源，可直接复核。

### 1.2 主键口径（重要）

设计规格原写 `seq_key = f"{year}_{SEQNO}"`，**在真实数据上不成立**：BRFSS 的 `SEQNO` 是"层（`_STSTR`）内序号"，单年内只有 1.7 万～2.6 万个不同取值（2019 年 418,268 行仅 17,419 个不同 `SEQNO`），直接用它做主键会触发 UNIQUE 冲突。

实测唯一性组合：`(_STSTR, SEQNO)` 在每一年内均与行数完全相等（2019：418,268 = 418,268；2023：433,323 = 433,323）。
因此主键修订为 **`seq_key = "{year}_{_STSTR}_{SEQNO}"`**，仅补足唯一性，不改变任何口径语义、不删除任何行。
验收证据：`COUNT(*) = COUNT(DISTINCT seq_key) = 2,136,402`（见第 7 节）。

## 2. 跨年调和映射表

BRFSS 年度问卷变量集逐年变化（2019 年 342 列 → 2023 年 345 列），以下 6 组变量必须在合并前统一，否则会出现整列丢失或数值错位。

| 统一后字段 | 2019 | 2020 | 2021 | 2022 | 2023 | 调和规则 |
|---|---|---|---|---|---|---|
| `has_copd` | CHCCOPD2 | CHCCOPD2 | CHCCOPD3 | CHCCOPD3 | CHCCOPD3 | 同义变量改名，直接映射（1=是/2=否/7/9→NULL） |
| `medcost` | MEDCOST | MEDCOST | MEDCOST1 | MEDCOST1 | MEDCOST1 | 同上（1=是/2=否/7/9→NULL） |
| `income_grp` | _INCOMG | _INCOMG | _INCOMG1 | _INCOMG1 | _INCOMG1 | _INCOMG1 的 6($100k–<$200k)、7(≥$200k) 折叠进 5(≥$50k)，还原 _INCOMG 的 5 档口径 |
| `persdoc` | PERSDOC2 | PERSDOC2 | PERSDOC3 | PERSDOC3 | PERSDOC3 | 1=只有一位/2=多于一位/3=没有，编码一致直接映射 |
| `race` | _RACE | _RACE | _RACE | **_MRACE2 + _HISPANC** | _RACE | 2022 年无 _RACE，用 _MRACE2 重建（见 2.1） |
| `heavy_drink` | — | — | — | _RFBING6 | _RFBING6 | 该变量 2022 年才开始发布，2019–2021 落 NULL |

> 说明：原始 `INCOME2/INCOME3`（细档收入）两代编码档位数不同（8 档 vs 10 档），本项目建模与聚合统一使用官方计算变量 `_INCOMG/_INCOMG1` 的 5 档口径，因此不单独输出细档收入。

### 2.1 2022 年种族重建规则（已用 2023 年数据验证）

`_RACE`（种族-族裔合并分组）：1 白人 2 黑人 3 印第安/阿拉斯加原住民 4 亚裔 5 夏威夷/太平洋岛民 6 其他 7 多种族 8 西班牙裔 9 不知道/拒答
`_MRACE2`（2022 年专有）：1 白人 2 黑人 3 印第安 4 亚裔 5 太平洋岛民 6 **多种族** 77 不知道 88 未选择 99 拒答

重建规则：`_HISPANC==1 → race=8`；否则 `_MRACE2 的 1–5 → 1–5`、`6 → 7（多种族）`、`77/88/99 → NULL`。

**验证证据**：在同时具备 `_RACE` 与 `_MRACE1` 的 2023 年上按同一规则重建，与官方 `_RACE` 完全一致的行占 **97.81%**；全部 9,484 条不一致记录都发生在 `_RACE=9（不知道/拒答）` 而 `_MRACE1` 有明确取值的情形，即"官方判为缺失、重建能给出类别"，**无一例把有值的行判错**。

## 3. 缺失码处理规则

### 3.1 通用规则

| 原始编码 | 含义 | 处理 |
|---|---|---|
| 7 | 不知道 / 不确定 | → NULL |
| 9 | 拒答 | → NULL |
| 77 | 不知道（两位数编码表） | → NULL |
| 99 | 拒答（两位数编码表） | → NULL |
| 88 | **"None"（0 天）** | **保留并转为 0**（仅 MENTHLTH / PHYSLTH 使用） |
| 空白 / 未问 | Not asked or Missing | → NULL |

**注意**：7 与 9 并非在所有变量中都是缺失码，例如 `EMPLOY1` 的 7=退休、`_MRACE1` 的 7=多种族、`CHECKUP1` 的 8=从未体检 都是**合法取值**。因此本项目按**逐变量白名单**处理缺失码（代码见 `02_clean_spark.py` 的 `clean()`），而不是对全表盲扫 7/9。

### 3.2 特殊规则

| 规则 | 处理 | 实测影响 |
|---|---|---|
| BMI 异常 | `bmi = _BMI5/100`；`bmi < 10` 或 `> 70` → NULL | **1,053** 行被判为异常置 NULL |
| BMI 原始缺失 | `_BMI5` 为空 | 213,753 行（占 10.0%） |
| 标签不可用 | 8 个慢病标志位**全部**为 NULL → `label_valid=0` 并剔除 | **972** 行（0.045%），清洗后 2,136,402 行 |
| `has_diabetes` 语义 | `DIABETE4`：1=是 → 1；2=妊娠期糖尿病、3=否、4=糖尿病前期 → 0；7/9 → NULL | 影响 12.7 万"妊娠期/前期"记录归为"否" |

## 6. 复现方式

```bash
# 环境（PySpark 必需）
set JAVA_HOME=D:\jdk17
set SPARK_HOME=D:\sparkhome
set PYSPARK_PYTHON=D:\期末作业\.venv\Scripts\python.exe

cd D:\期末作业\慢性病患者健康风险预测与干预
python pipeline/01_download.py      # 采集 + SHA256 校验（首次 17.0 秒；已存在则 0.3 秒跳过）
```

三个脚本均幂等：`01` 校验大小后跳过、`02` 覆盖写出、`06` 删除旧库后重建。
