## 一、方案目标

### 1.1 业务目标

以慢性病（糖尿病、冠心病、心肌梗死、卒中、慢阻肺、哮喘、慢性肾病、抑郁）为核心对象，回答三个递进问题：

1. **现状是什么**——五年间 8 类慢病的患病率、共病结构如何在年龄、收入、教育、州际三个维度上分布；
2. **风险从哪来**——吸烟、肥胖、缺乏运动、重度饮酒、费用障碍等可干预因素与共病的关联强度（调整后 OR）有多大；
3. **谁需要先干预**——给定一个个体的可采集特征，输出其共病阳性概率与风险等级，并给出可执行的干预建议。

### 1.2 技术目标（可量化）

| 编号 | 目标 | 验收阈值 | 实际达成 |
|---|---|---|---|
| T1 | 数据规模 | ≥ 200 万条真实记录 | 2,137,374 条（清洗后 2,136,402 条） |
| T2 | 原始数据可追溯 | 保留原始副本 + 校验 | parquet 原件 + SHA256SUMS + CSV 副本 |
| T3 | 分析引擎 | 具备分布式计算能力 | PySpark 4.2 清洗与 EDA + Spark MLlib 建模 |
| T4 | 模型效果 | 时间外推测试集 AUC ≥ 0.75 | LightGBM 0.7740（5 折 CV 0.7815±0.0012） |
| T5 | 服务化 | 提供可调用的在线预测接口 | FastAPI 12 个路由，聚合查询 17~37ms |
| T6 | 可视化 | 覆盖现状/因素/分层/地图/模型五类视图 | 9 个面板 + 4 图联动下钻 |
| T7 | 工程质量 | 自动化测试通过 | pytest 43 项全绿 |

### 1.3 交付目标

一套**数据—分析—模型—服务—可视化**闭环的可复现工程，加一份可直接答辩的报告与 17 页 PPT，以及一个解压即用的便携版。

## 二、主要思路

### 2.1 一句话概括

**用真实公开微观调查数据，先在分布式引擎里把"脏"洗成"净"并冻结口径，再用星型模型把明细沉淀为可查询的指标层，然后在这个稳定的口径上做统计推断与机器学习双轨建模，最后把模型与指标一起包装成 REST 接口和可视化面板。**

### 2.2 五条设计原则

**原则一：原始数据只读取、不修改。**
所有清洗都在内存/中间层完成，`data/raw/` 下的 5 个 parquet 保持字节级不变，另存 SHA256 校验清单。这样任何一次"口径写错了"的返工都只是重跑脚本，不会毁掉证据链。

**原则二：口径先行、冻结后再建模。**
BRFSS 的编码陷阱极多（详见 5.4）。我们在动任何模型之前，先把 8 类慢病标志、9 个危险因素的方向与缺失约定写进 `_设计规格.md` 并冻结。**教训来源**：开发中出现过把"1=否/2=是"的字段当成"1=是"，导致重度饮酒率被算成 86.73%（真实值 13.27%）——方向错一次，结论反一次，且模型照样能训练出高 AUC，错误会静默通过。

**原则三：明细与聚合分离（星型模型）。**
事实表存 213 万行个体记录，聚合表预计算患病率/暴露率/分层分布。接口只查聚合表，实测响应从 2322ms 降到 37ms。聚合表可从明细重建（`scripts/rebuild_aggregates.py`），不存在"只能手工维护"的状态。

**原则四：标签必须与特征在时间上可分离。**
特征集刻意分成两套：Set-A（19 个人口学+行为+就医可及性特征）与 Set-B（额外并入自评健康、心理不良天数等）。Set-B 的 AUC 高出 **0.0462**，但自评健康是疾病的**后果**而非前因——用它预测等于让模型偷看答案。因此正式模型锁定 Set-A，Set-B 只作为泄漏对照实验写进报告。

**原则五：评价用时间外推，不用随机切分。**
训练集 2019—2022（1,703,267 行），测试集 2023（433,135 行）。同一份问卷的相邻年份高度相关，随机切分会让指标虚高；按年外推才等价于"用历史预测未来"的真实部署场景。

### 2.3 技术路线主线（六环节）

```
①数据获取          ②清洗治理          ③存储建模          ④统计分析          ⑤机器学习          ⑥服务与可视化
BRFSS 5年parquet → PySpark 类型/编码/  → SQLite 星型模型 → 加权患病率        → sklearn 6组      → FastAPI 12路由
(213.7万行)        缺失/主键统一        (1事实4维4聚合)   + Logistic OR      + Spark MLlib      + ECharts 9面板
                                                                             + PyTorch MLP      + JWT 鉴权
```

### 3.2 各层职责与边界

| 层 | 目录 | 职责 | 明确不做 |
|---|---|---|---|
| 数据层 | `data/raw/` | 存放只读原件与校验清单 | 不做任何字段修改 |
| 计算层 | `pipeline/` | 清洗、EDA、特征、训练、建库 | 不提供对外接口 |
| 存储层 | `db/` | 星型模型 + 预计算聚合 | 不承载业务逻辑 |
| 服务层 | `api/` | 契约、鉴权、查询、推理 | 不在请求内做训练或全表扫描 |
| 展示层 | `web/` | 渲染与交互 | 不直连数据库 |
| 治理层 | `scripts/`、`tests/`、`docs/` | 验收、重建、文档 | — |

### 3.3 三条关键数据流

**流A · 离线全量重建**：`01_download` → `02_clean_spark` → `03_eda_spark` → `04_features` → `05_train` → `06_build_db`。由 `pipeline/run_all.py` 串联，一次跑完全链路。

**流B · 在线查询**：浏览器 → `GET /api/v1/*` → `repository.py` 参数化 SQL → 聚合表 → JSON 信封 → ECharts 渲染。全部为聚合查询，无全表扫描。

**流C · 在线推理**：表单提交 → `POST /api/v1/predict`（Bearer 令牌）→ `predictor.py` 加载 LightGBM、按 Set-A 19 特征顺序组装、缺失填中位数 → 输出 probability / risk_level / model_info / missing_features / interventions。

## 四、技术选型与理由

### 4.1 选型对比表

| 维度 | 候选方案 | 最终选择 | 理由 |
|---|---|---|---|
| 计算引擎 | pandas / **PySpark** / Dask | PySpark 4.2（聚合场景回退 pandas） | 213 万行 × 593 列已超出单机 pandas 舒适区；课程本身要求体现分布式能力。但聚合类操作用 pandas 更省事，故两者并用而非教条化 |
| 中间落盘 | Spark df.write.parquet / **Arrow→pandas 分批写** | Arrow 分批写 | 本机 Spark 4.2 缺 winutils.exe，df.write 必抛 HADOOP_HOME 异常。清洗算子仍在 Spark 内完成，只有落盘环节换通道，分布式优势保留 |
| 存储 | MySQL / PostgreSQL / **SQLite** / Parquet 直查 | SQLite | 单机交付、零安装、可随包分发；213 万行 + 索引下单表聚合稳定在 40ms 内。代价是无并发写能力——但本项目是只读分析场景，该限制不构成瓶颈 |
| 建模（主力） | **LightGBM** / XGBoost / 随机森林 / 逻辑回归 | LightGBM | 表格数据 SOTA 级别；对缺失值原生友好（BRFSS 大量"拒答/不知道"）；训练快、可解释（feature_importance） |
| 建模（基线） | 逻辑回归 / 决策树 | 逻辑回归 + 随机森林 | 必须有可对比基线，否则 0.7740 这个数字没有意义。LR 提供 OR 的统计解释，RF 提供非线性基线 |
| 建模（对照） | **Spark MLlib** / PyTorch | 两条都做 | MLlib 证明分布式口径与 sklearn 一致（LR 0.7444 vs 0.7447，GBT 0.7671 vs 0.7740）；PyTorch MLP 证明深度模型在此特征集上并无增益（0.7699） |
| 服务框架 | Flask / Django / **FastAPI** | FastAPI | 原生异步、Pydantic 校验、自动 OpenAPI 文档；本机 uvicorn 单进程即可支撑演示 |
| 鉴权 | Session / **JWT** | JWT | 无状态、前端易携带、便于演示"无令牌 401 → 登录 → 带令牌 200"的完整链路 |
| 可视化 | Tableau / **ECharts** / Plotly / Superset | ECharts（本地内置） | 免授权、可离线、支持地图与联动；echarts.min.js 与 us-states.geojson 随仓库分发，断网可用 |
| 前端组织 | React / **原生 + Vue3 双版** | 双版 | 原生版零构建依赖、双击即开，适合答辩；Vue3 版演示组件化能力（加分项） |
| 采集练习 | requests / **Scrapy + Selenium** | 两者都做 | Scrapy 覆盖静态站点与管道；Selenium 覆盖 JS 渲染与驱动管理 |
| 部署 | 手工 / **Docker + 便携包** | 两者都备 | Dockerfile/compose 提供标准做法（本机无 Docker，仅做 YAML 校验）；便携包解决"老师电脑没环境"的真实痛点 |

### 4.2 被否决的方案及原因

- **放弃 CDC 官网直连**：www.cdc.gov 对本机返回 403，HEAD/GET/curl 全部失败；改用 HuggingFace 镜像 LoneWolfgang/brfss-llcp 的同一份 LLCP 数据，来源可核验。
- **放弃在 Spark 内完成全部分析**：`03_eda_spark.py` 中 Logistic 设计矩阵出现过秩亏（常量列 age_unknown、sex_unknown），statsmodels 只告警不报错、系数不可识别。改为用 20 万行抽样的带主元 QR 判数值秩后剔除常量列——**告警不等于没问题，必须主动验证数值秩**。
- **放弃"高 AUC 就是更好"的判断**：见原则四。Set-B 的 0.8202 是泄漏产物，不作为成果。

## 五、数据模型

### 5.1 三层数据形态

| 层 | 位置 | 规模 | 说明 |
|---|---|---|---|
| 原始层 | `data/raw/*.parquet` | 2,137,374 行 × 342~345 列 | 五年并集 593 列，交集仅 160 列，433 列只存在于部分年份 |
| 明细层 | `fact_brfss` | 2,136,402 行 × 37 列 | 统一编码、重算主键、派生指标 |
| 指标层 | 4 张聚合表 | 45 / 2376 / 45 / 35 行 | 预计算，供接口直接读取 |

### 5.2 事实表 fact_brfss（37 列）

| 分组 | 字段 | 说明 |
|---|---|---|
| 主键 | `seq_key` | `{year}_{_STSTR}_{SEQNO}` 拼接。**SEQNO 是层内序号不是全局唯一**：2019 年 418,268 行只有 17,419 个不同值 |
| 时间 | `year` | 2019—2023 |
| 地理 | `state_fips`、`state_name` | 54 个州/属地 |
| 人口学 | `age`、`age_grp`、`sex`、`race`、`education`、`income_grp`、`marital` | 归一化编码 |
| 慢病标志（8） | `diabetes`、`coronary`、`heart_attack`、`stroke`、`copd`、`asthma`、`kidney`、`depression` | 全部 0/1，"1=患有" |
| 危险因素（9） | `smoke_status`、`bmi`、`obese`、`phys_activity`、`heavy_drink`、`checkup`、`checkup_over_1y`、`medcost_barrier`、`usual_doctor`、`diff_walk` | bmi 为连续值，其余 0/1 或有序码 |
| 派生 | `chronic_count`、`multimorbidity`、`genhlth`、`menthlth`、`physhlth`、`weight_raw` | multimorbidity = chronic_count ≥ 2 |

### 5.3 维表与聚合表

| 表 | 行数 | 用途 |
|---|---|---|
| dim_year | 5 | 年份维度 |
| dim_state | 54 | 州维度（含 FIPS，供地图匹配） |
| dim_age_group | 13 | 年龄组（18-24 … 80+） |
| dim_income_group | 8 | 收入 8 档 |
| dim_education | 6 | 教育 6 档 |
| dim_chronic | 9 | 8 类慢病 + 合计 |
| agg_prevalence_year | 45 | 年 × 慢病 患病率（含加权/未加权） |
| agg_prevalence_state | 2376 | 州 × 慢病 |
| agg_risk_factor | 45 | 年 × 危险因素 暴露率 |
| agg_risk_stratum | 35 | 风险分层 × 慢性病数量 |
| model_metrics | 43 | 模型 × 指标 长表 |
| audit_pipeline | — | 每次采集/构建的审计记录 |

索引：idx_fact_year、idx_fact_state、idx_fact_diabetes、idx_fact_multimorbidity、idx_fact_age_grp。

### 5.4 四个必须知道的口径陷阱

1. **主键不唯一**：SEQNO 与 _PSU 均为层内序号，不能单独作主键；(_STSTR, SEQNO) 组合去重后与总行数相等，故可用，并加上年份前缀构成 seq_key。
2. **编码方向不一致**：慢病标志位是"1=是"，但 _RFBING6（重度饮酒）是"1=否/2=是"，_TOTINDA（运动）是"1=有/2=无"。若不逐字段核对方向，重度饮酒率会从 **13.27% 变成 86.73%**。本项目已将全部二值字段统一为"1=字段名所述状态成立"。
3. **CHECKUP1 不是"是否体检"**：编码为 1=12月内 / 2=2年内 / 3=5年内 / 4=5年以上 / **8=从未**。按 =1 统计会得出"81% 的人从未体检"这一荒谬结论；正确口径是 checkup_over_1y = checkup > 1。
4. **跨年列不一致**：五年并集 593 列但交集只有 160 列，433 列只存在于部分年份。任何跨年分析必须先对齐到交集，否则会出现整列缺失却被当作"真实零值"。

## 六、API 清单

统一响应信封：

```json
{ "code": 0, "message": "success", "data": {}, "traceId": "...", "timestamp": "..." }
```

| # | 方法 | 路径 | 说明 | 鉴权 |
|---|---|---|---|---|
| 1 | GET | / | 服务根路径，返回服务名与文档地址 | 否 |
| 2 | POST | /api/v1/auth/login | 登录并签发 JWT（TTL 3600s） | 否 |
| 3 | GET | /api/v1/auth/me | 查询当前令牌身份 | 是 |
| 4 | GET | /api/v1/health | 健康检查（数据库连通性与行数） | 否 |
| 5 | GET | /api/v1/overview | 总览 KPI（总样本、年份跨度、共病率、病种/州数） | 否 |
| 6 | GET | /api/v1/chronic/prevalence | 各慢病患病率（可按 year、state 过滤） | 否 |
| 7 | GET | /api/v1/trend | 指标年度趋势 | 否 |
| 8 | GET | /api/v1/risk/factors | 危险因素暴露率 | 否 |
| 9 | GET | /api/v1/risk/stratify | 风险分层分布 | 否 |
| 10 | GET | /api/v1/geo/states | 州级指标（地图用，含 FIPS） | 否 |
| 11 | GET | /api/v1/model/metrics | 模型指标与跨模型对比 | 否 |
| 12 | POST | /api/v1/predict | 在线个体风险预测 | **是** |

响应码契约：0 成功；400 参数不合法；401 鉴权失败（缺令牌/令牌无效/令牌过期）；404 资源不存在；500 服务内部错误。

X-Response-Time 响应头记录服务端耗时，前端可直接展示（实测预测链路 8952.82ms 中的绝大部分是首次模型加载，后续请求为毫秒级）。

## 七、实施步骤

### 阶段 M0 · 立项与口径冻结（已完成）

1. 读取两份课程要求，确认评价维度与必交材料；
2. 确定数据源为 BRFSS LLCP 2019—2023，下载并核对行数（2,137,374）；
3. 逐字段核对编码方向，把 8 类慢病、9 个危险因素、缺失约定写入 `_设计规格.md` 并冻结。

**产出**：`_设计规格.md`。**风险点**：数据源可达性——CDC 官网 403，故先做了镜像可用性验证再动手。

### 阶段 M1 · 数据获取与清洗（已完成）

1. `01_download.py` 拉取 5 年 parquet，建立 SHA256 校验清单与原始副本；
2. `02_clean_spark.py` 在 Spark 内完成类型统一、编码归一、主键重算（seq_key）、派生列（chronic_count、multimorbidity、checkup_over_1y）；
3. 落盘改用 Arrow 分批写，绕开缺 winutils.exe 的限制。

**产出**：清洗后 2,136,402 行 × 37 列。**踩坑**：Spark 写 parquet 抛 HADOOP_HOME 异常；中文路径导致 JVM classpath 崩（改用 ASCII 目录联接 D:\jdk17、D:\sparkhome）；pandas 3.x 与 PySpark 4.2 不兼容（回退 2.3.3）。

### 阶段 M2 · 建库与指标体系（已完成）

1. `06_build_db.py` 建 1 事实表 + 6 维表 + 4 聚合表 + 2 元数据表，建 5 个索引；
2. 聚合表从明细计算，不手工维护；
3. 发现聚合表整体变空后，补写 `scripts/rebuild_aggregates.py` 支持从明细重建。

**产出**：`db/chronic_risk.db`（361MB）。**收益**：/risk/factors 224ms→17ms，/risk/stratify 2322ms→37ms。

### 阶段 M3 · 统计分析与建模（已完成）

1. `03_eda_spark.py` 出 12 张图 + eda_metrics.json + hypothesis_metrics.json，含加权患病率、Logistic 调整后 OR、剂量反应关系；耗时 193.5s；
2. `04_features.py` 生成 Set-A（19）/Set-B（24）两套特征与 dataset.parquet；
3. `05_train.py` 训练 6 组 sklearn 模型，时间外推评估 + 5 折 CV；
4. `07_spark_mllib.py` 用 Spark MLlib 复现 LR/GBT 作为口径对照；
5. `10_tuning.py` 做网格调优实验；`11_seaborn_figures.py` 出统计图族。

**产出**：LightGBM Set-A AUC 0.7740 / PR-AUC 0.4595 / F1 0.4619 / Brier 0.2019，CV 0.7815±0.0012。**关键判断**：调优后测试 AUC 反而 -0.0007，说明默认参数已接近该特征集上限，如实记录不粉饰。

### 阶段 M4 · 服务化与可视化（已完成）

1. `api/` 实现 12 个路由、统一信封、X-Response-Time 中间件、JWT 鉴权、模型推理与干预规则匹配；
2. `web/` 原生版 9 个面板 + 4 图联动下钻；`web/vue/` 组件化版本；
3. `tests/` 补至 43 项 pytest 用例。

### 阶段 M5 · 交付与验收（已完成）

1. 生成报告与 PPT，逐条对齐模板章节；
2. 构建便携版（内嵌 Python 3.12.10 + 依赖 407MB + 应用），可移植性在全新临时路径验证通过；
3. GitHub 建仓上传（112 文件 / 11.08MB / 36 次提交）。

## 十、风险与应对

| 编号 | 风险 | 影响 | 应对措施 | 实际结果 |
|---|---|---|---|---|
| R1 | 公开数据源不可达 | 项目无法启动 | 预先探测多个镜像，固化 SHA256 | CDC 官网 403，改用 HuggingFace 镜像成功 |
| R2 | 口径误判导致结论反转 | 静默错误，模型仍高 AUC | 口径冻结 + 逐字段核对方向 + 交叉复核 | 捕获 3 个致命缺陷（主键/编码方向/CHECKUP1） |
| R3 | 标签泄漏虚高指标 | 成果不可信 | 双特征集对照，锁定可解释特征集 | 识别出 0.0462 AUC 的泄漏代价 |
| R4 | 分布式环境不可用 | 无法体现大数据能力 | 算子留在 Spark，仅落盘换通道 | 清洗与 EDA 全部在 Spark 内完成 |

| R7 | 超大文件无法入库 | 仓库不完整 | .gitignore 排除 361MB 数据库，仅提交 schema | 仓库 11.08MB，克隆后可重建 |
