# 前端说明（可视化大屏）

> 项目：基于 BRFSS 大数据的慢性病患者健康风险预测与干预分析
> 模块：前端展示层（可视化）　|　目录：`web/`
> 署名：许宇翔 / 20240517108　|　课程：大数据分析课程设计

本文档说明技术选型、每个图表的选型论证、交互链路、本地启动方式、验证证据与已知限制。
页面中出现的**每一个数字都来自 `POST/GET /api/v1/*` 的真实响应**，前端不含任何硬编码业务数值
（`js/dict.js` 只保存契约元数据：字段名、指标白名单、FIPS 编码、干预规则文案）。

## 1. 技术选型

| 关注点 | 选择 | 理由 |
|---|---|---|
| 渲染框架 | 原生 HTML + CSS + 原生 JS（IIFE，无构建） | 课程要求"原生 HTML/CSS/JS"；零依赖零构建，现场演示双击即开，不会因为 npm 安装或构建产物缺失翻车 |
| 图表库 | **ECharts 5.5.1，本地内置** `web/vendor/echarts.min.js` | 地图、双轴、堆叠、仪表盘一套库全覆盖；**不引 CDN**，断网可正常渲染 |
| 地图数据 | `web/vendor/us-states.geo.js`（内嵌 JS 变量） | 见 §1.2：既离线可用，也支持 `file://` 直接打开 |
| 模块方式 | 传统 `<script>` + 命名空间 `window.BRFSS` | ES Module 在 `file://` 下会被 CORS 拦截（`type="module"` 无法本地直开），为兼容"双击打开"场景改用 IIFE |
| 请求 | `fetch` + `AbortController` 超时 + 指数退避重试 | 见 §2 健壮性；不引 axios/jQuery |
| 样式 | 单文件 CSS + CSS 变量 | 一套色板与字号层级集中在 `:root`，改主题只改一处 |

### 1.2 地图数据为何内嵌成 JS

1. `file://` 场景下浏览器禁止 `fetch` 本地文件，纯 `.geojson` 无法加载；内嵌为
   `window.BRFSS_US_MAP = {...}` 后，双击 `index.html` 也能出图。
2. 源数据（PublicaMundi MappingAPI `us-states.json`，公共领域）做了两处几何归一：
   - `properties.name` 统一改为两位 FIPS 编码（例：`"06"`），使 API 的 `stateFips` 可直接与地图绑定；
   - 剔除阿拉斯加阿留申群岛（经度 < −169° 的跨 180° 经线小岛），并把阿拉斯加、夏威夷按
     **内嵌（inset）** 方式重定位到主图左下角——否则整幅美国地图会被压扁成一条细带。
3. 主图之外的颜色语义由 `visualMap` 连续分段承担，单位与 `/trend` 保持一致（率类为 %）。

## 2. 区块与接口（10 个区块 / 9 个接口全用上）

| # | 区块 | 接口 | 图表类型 | 单位与口径 |
|---|---|---|---|---|
| 1 | 核心指标总览（6 卡片） | `GET /overview` | KPI 卡片 | 总样本 n、慢病类数、共病率（分子/分母）、年份跨度、覆盖州数、人均慢病数 |
| 2 | 各慢病患病率（排序） | `GET /chronic/prevalence?year=&state=` | 横向条形图 | 率(%)，n = 该病标志位有效样本 |
| 3 | 指标年度趋势 | `GET /trend?metric=` | 折线图（可切换 15 个指标） | 率类 %，样本量为人次；tooltip 给分子/分母 |
| 4 | 州级指标地图 | `GET /geo/states?metric=` | 分级统计地图 choropleth | 率(%)，tooltip 给 n = 分母 |
| 5 | 可干预危险因素暴露率 | `GET /risk/factors?year=` | 横向条形图 | 暴露率(%)，n = 该字段非缺失记录 |
| 6 | 风险分层与慢病数分布 | `GET /risk/stratify` | 100% 堆叠条 + 柱状图 | 占比(%) 与样本量(人) |
| 7 | 模型指标对比 | `GET /model/metrics` | 分组柱状图 | 指标值 0–1（AUC 等） |
| 8 | 年龄组共病率与样本量 | `GET /risk/stratify`（`byAge`） | 柱线组合双轴 | 柱=样本量(人)，线=共病率(%) |
| 9 | 地图下钻明细 | `GET /chronic/prevalence?state=<FIPS>` | 迷你条形列表（DOM） | 率(%)，n = 该州样本量 |
| 10 | 在线个体风险预测 | `POST /predict` | 仪表盘 + 结果表 + 建议列表 | 阳性概率(%)、风险等级、阈值、缺失特征、延迟 |

> 说明：`/risk/stratify` 同时提供 `levels`（风险分层）、`distribution`（慢病数分布）与 `byAge`（年龄组），
> 前端**只请求一次**并复用于区块 6 与区块 8，避免重复打接口。

### 2.1 统一信封与错误处理约定

```json
{"code":0,"message":"ok","data":{...},"traceId":"...","timestamp":1792402758028}
```

`api.js` 的规则：

- `code === 0` → 返回 `data`；
- `code !== 0` → 抛 `ApiError`，携带 `code / message / traceId / url`，由面板渲染成红色错误块；
- **重试只对"基础设施类"失败生效**：超时（AbortError）、网络失败、HTTP 5xx、`code ∈ {500, 1003}`；
  业务错误（如 `400` 参数越界、`1001` 模型未就绪、`1002` 预测失败）**立即失败不重试**，
  因为重试不会改变结论，只会拖长演示等待。

真实响应样例（节选，演示库 600,000 行）：

```json
{"code":0,"message":"ok","data":{"totalSamples":600000,
 "yearSpan":{"min":2019,"max":2023,"years":5},
 "stateCount":54,"chronicTypes":8,
 "multimorbidityCases":108967,"multimorbidityValid":599747,
 "multimorbidityRate":0.181688,"avgChronicCount":0.75,
 "diabetesPrevalence":0.135159},"traceId":"20da77d7e5e849b6a7bec71697c8b606","timestamp":1792402758028}
```

```json
{"code":0,"message":"ok","data":{"metric":"multimorbidity_rate","label":"共病率","unit":"ratio",
 "series":[{"year":2019,"value":0.18304,"numerator":21959,"denominator":119968},
```

### 2.2 契约细节处理（不猜字段名，按实测响应写解析）

| 实测发现 | 前端处理 |
|---|---|
| `/geo/states` 的 `stateName` 绝大多数只是 FIPS 数字字符串（仅个别州有英文名，如 `California`） | 州名以 `js/dict.js` 的 FIPS→中文州名/简称字典为准（静态编码表，非业务数据）；`stateName` 不参与展示 |
| `/geo/states` 返回 54 个地区，包含 60/66/69/78 等属地，而州界几何只有 50 州 + DC + PR | 无几何的 FIPS 不进入地图 series，但仍参与州下拉筛选与下钻请求；地图 tooltip 缺数据时显示"无数据（该州未返回）" |
| `/risk/factors` 中 `heavy_drink` 的 `validSamples` 仅 216,804（分母只含"有饮酒记录者"），率高达 86% | 条形 tooltip 明确写"分母为该字段非缺失记录"，并在页面提示中说明各因素分母口径不同 |
| `/trend` 与 `/geo/states` 共用一套 `metric` 白名单（15 个） | 两个下拉共用 `dict.METRICS`；联动时两个下拉同步切换 |
| `/model/metrics` 返回的是"模型×指标"长表（演示库仅 `auc` × 2 模型） | 前端按 `model_name` 分组、`metric` 为系列动态渲染，指标增减无需改代码 |
| `/predict` 可能返回 `code=1001`（模型未就绪）、`400`（特征越界） | 分别给出针对性文案与"重试"按钮（见 §6 截图 06） |

## 3. 图表选型论证（为什么用这个图型）

1. **KPI 卡片（区块 1）**：4 个核心口径 + 2 个补充口径，属于"数值优先"的结论型信息，
   大字 + 脚注（分子/分母）比图表更快传达；脚注保证每个数字可追溯。
2. **各慢病患病率 → 横向条形（区块 2）**：比较 8 个类别的**量级差**并需要**排序**。
   竖排类别名（"慢性肾病"等）在横轴会挤成一列或被迫旋转 45°，横向条形标签水平可读、且
   长度直接映射患病率大小。**不用饼图**：饼图比较相近比例（5.61% vs 5.62%）几乎无法分辨。
3. **年度趋势 → 折线（区块 3）**：横轴是连续时间（2019–2023），折线是"趋势 + 斜率"的标准编码；
   面积渐变只做视觉引导，不做面积比较（避免误导为总量）。切换指标时保留坐标系与单位说明。
4. **州级指标 → 分级统计地图（区块 4）**：数据自带地理维度，空间聚集（如东南部高、西部低）只有地图能表达；
   颜色映射用连续 `visualMap` 并显式标出最小/最大值。**不用气泡地图**：气泡面积在 60 个州同屏时互相遮挡且难比较。
5. **危险因素暴露率 → 横向条形（区块 5），而非雷达**：
   10 个因素的分母口径**互不相同**（重度饮酒只统计有饮酒记录者、心理不良只统计有回答者），
   雷达图会把不同分母的率放进同一个半径尺度，视觉上暗示"同一可比体系"，属于误导；
   条形图能并列展示率与 n，排序后还能一眼看出"肥胖/缺乏运动/心理不良"三个高杠杆靶点。
6. **风险分层 → 100% 堆叠条（区块 6 上）**：三档构成是"整体=100%"的部分-整体关系，
   堆叠条可直接读数（81.8% / 15.5% / 2.7%）且支持 3 段以上；环图在 3 段时虽可行，
   但与页面其他区块的直角坐标体系不一致，故统一用堆叠条。
7. **慢病数分布 → 柱状（区块 6 下）**：0/1/2/3/≥4 是有序档位且样本量差异达 20 倍，
   柱状图比较绝对量最直观；若用饼图则 ≥4 种（2.7%）这样的小扇区几乎不可见。
   （页面同时遵守"类别数 > 8 禁用饼图"的约束：本页所有构成类图表类别数均 ≤ 5 且统一使用条形。）
8. **模型指标对比 → 分组柱状（区块 7）**：跨模型同指标比较，柱高对齐同一 0–1 基线才可比；
   若用折线会把"离散模型"错误地暗示成连续序列。
9. **年龄组 → 柱线组合双轴（区块 8）**：样本量（万级）与共病率（%）差 4 个数量级，
   同一轴会把率曲线压成一条水平线；双轴 + 明确轴名和单位是唯一不丢信息的选择。
10. **在线预测 → 仪表盘 + 结果表（区块 10）**：单一概率值用仪表盘表达"在 0–100% 区间中的位置"，
    并叠加后端返回的判定阈值（中 ≥10%、高 ≥30%），比纯数字更易读；明细仍以表格给出精确值。

## 4. 交互链路

### 4.1 筛选器联动（年份 / 州）

```
年份下拉 ──┬─→ GET /chronic/prevalence?year=Y&state=S  → 区块 2 重绘（排序 + 点击联动）
           └─→ GET /risk/factors?year=Y                → 区块 5 重绘
州下拉   ──┴─→ GET /chronic/prevalence?year=Y&state=S  → 区块 2 重绘
              GET /chronic/prevalence?state=S          → 区块 9 下钻明细
              GET /geo/states?metric=M                 → 区块 4 重绘并保持选中态
```

顶栏提示条写明"年份/州影响哪些图"：`/trend`、`/geo/states`、`/risk/stratify`、`/overview`
在冻结契约里没有年份/州参数，因此**不假装过滤**，只让受影响的图表刷新。

### 4.2 地图下钻

1. 点击地图任一州（`series.click`）→ `drillInto(fips)`；
2. 同步"州"下拉、写入 `state.filters.state`、重绘地图（单州选中态 + 州简称如 `CA` 标签）；
3. 请求 `/chronic/prevalence?state=<FIPS>` → 区块 9 渲染该州 8 类慢病患病率迷你条形 + 样本量；
4. 区块 9 提供「把该州应用到全局筛选」与「清除下钻」两个出口，避免用户卡在下钻状态。

### 4.3 图表间联动高亮

- **慢病条形 → 趋势图 + 地图**：点击"哮喘"→ `asthma_rate`，两个下拉同步，两个图重绘，右下角 toast 说明来源；
- **危险因素条形 → 趋势图 + 地图**：肥胖/现在吸烟/缺乏运动/重度饮酒 4 个因素有对应指标，其余因素
  因契约未提供独立趋势指标，给出明确提示而不是静默无响应；
- **风险分层段 → 明细提示**：点击堆叠段弹出口径（等级规则 + 样本 + 占比）。

联动除了"换数据"，还做**语义色一致**：每个慢病/因素指标在 `js/dict.js` 有固定展示色，
趋势折线切换后取用同一颜色（例：点击"哮喘"→ 折线变绿，与哮喘条形同色），
这样用户不需要读文字也能确认"这两张图说的是同一件事"。自动化断言结果：

```
applyMetricLink('asthma_rate')
→ trendSelect = asthma_rate, geoSelect = asthma_rate, trendLineColor = #34d399
```

### 4.4 在线预测

```
表单（12 个可选特征，字段名 = fact_brfss 列名）
   → POST /api/v1/predict  {age_grp,sex,bmi,smoker3,...}
   → 仪表盘（probability）、风险等级、阈值、模型文件名、缺失特征数、接口延迟
   → 干预建议：按"命中规则 × 风险等级"生成，每条附 /risk/factors 的人群暴露率（真实数字）
```

干预建议为课程项目设定的规则模板（不是临床指南），页面末尾已标注该免责说明。

## 5. 健壮性设计（不允许白屏 / 静默失败）

| 机制 | 实现位置 | 行为 |
|---|---|---|
| 加载骨架 | `.skeleton` + shimmer | 每个面板独立骨架，互不阻塞 |
| 请求失败 | `showError()` | 红色错误块，显示 `message（code）+ 已尝试次数 + traceId` + 「重试」按钮 |
| 空数据 | `showState(kind='empty')` | 琥珀色"暂无数据"占位，并说明是哪个筛选条件下为空 |
| 超时重试 | `api.js` | 单请求超时 **12s**（真库 213 万行时 `/risk/stratify` 约 6s）；最多重试 **3 次**，退避 **300 → 600 → 1200ms**（即最多 4 次尝试）；仅对超时/网络/5xx/1003 生效 |
| 请求去重 | `app.js: fetchOnce` | `/risk/stratify` 被"风险分层"与"年龄组"两个面板共用，只发一次请求（并发去重 + 成功后缓存），避免在大库上跑两遍 6s 查询 |
| 全局 JS 异常 | `window.error` / `unhandledrejection` | 顶部红条显性报错，并在 `<body data-js-errors="n">` 上计数（便于自动化断言"无 JS 异常"） |
| 后端不可用 | 顶栏状态胶囊 | 变红提示"后端未连接"并给出启动命令（title 提示） |
| 地图/图表库缺失 | `init()` 的 try/catch | 地图面板单独降级报错，其余区块照常工作 |
| 自适应尺寸 | `ResizeObserver` + `resize` 防抖 | 窗口/布局变化后图表 resize，不出现空白画布 |
| API 地址可覆盖 | `?api=http://127.0.0.1:8000`（写入 localStorage） | 便于把前端指向另一台/另一个端口的后端而无需改代码 |

## 9. 已知限制

1. **地图地域**：州界几何只含 50 州 + DC + PR；关岛(66)、美属维尔京(78) 等属地仅能通过下拉筛选与下钻体现，
   不出现在地图上（地图 tooltip 已对缺数据地区给出说明）。
2. **州名**：接口 `stateName` 多数只回 FIPS 数字，页面用本地 FIPS 字典补全中文名；如需权威英文名，
   建议后端在 `dim_state` 中补 `state_name` 字段（前端无需改动）。
3. **筛选维度受契约约束**：`/trend`、`/geo/states`、`/risk/stratify`、`/overview` 没有年份/州参数，
   因此筛选器只影响 `/chronic/prevalence` 与 `/risk/factors`；页面已显式标注，不做假过滤。
4. **在线预测依赖模型文件**：`/predict` 需要 `artifacts/model/model.joblib`；模型未生成时接口返回
   `code=1001`，前端展示失败态与重试（截图 06）。本文档的截图 04 使用**临时联调模型**
   （`_tmp_fe/model/model.joblib`，用演示库训练的 LightGBM，仅用于验证第 9 个接口的前端链路，
   不进入交付目录）；真实模型由 `pipeline/05_train.py` 产出，产出后无需改前端即可复用。
5. **模型指标面板当前为空态**：真库 `model_metrics` 表尚无记录（`/model/metrics` 返回 `count=0`），
   面板按"空数据占位"处理并提示"需先运行 pipeline/05_train.py"。该脚本写入指标后，图表自动按
   "模型 × 指标"动态出系列，**前端无需改动**；届时重跑截图脚本即可更新 `01/02` 两张图。
6. **截图复跑方式**：截图由 `_tmp_fe/capture.mjs`（Edge Headless + DevTools Protocol，**临时联调脚本，不入交付目录**）
   生成：`node capture.mjs`（默认 8000 端口）、`MODE=predict-only API_BASE=http://127.0.0.1:8001 node capture.mjs`。
   控制台断言、DOM 断言与截图在同一脚本内完成。
7. **无自动刷新**：页面为一次性加载 + 手动重试，未实现轮询/WebSocket（演示场景不需要，且避免无谓请求）。
8. **无多语言**：仅中文文案；字段名、接口路径保留英文以对齐契约。
9. **重度饮酒率口径**：该指标分母为"有饮酒记录者"（`validSamples` 显著小于全样本），
   与肥胖/缺乏运动等全样本率不可直接横比；页面 tooltip 与提示已标注。
